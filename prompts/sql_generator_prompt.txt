PLAYER LOOKUP:
  dim_player: person_id, first_name, last_name, birth_date, height_inches,
              body_weight_lbs, draft_year, from_year, to_year,
              is_guard, is_forward, is_center (BOOLEAN)
  → Join to stats via person_id

TEAM LOOKUP:
  dim_team: team_id (COMPOSITE KEY with season_founded — many rows per team!)
  → team_name = 'Warriors' (NOT 'Golden State Warriors')
  → team_abbrev = 'GSW', 'LAL', 'BOS', 'MIA', 'CHI', etc.
  → WARNING: dim_team has PRIMARY KEY (team_id, season_founded).
    Joining ON team_id alone creates CROSS PRODUCT → inflated counts + NULL season_year.
    PREFER v_team_current (1 row per team) for name lookups.
    For team win stats, use fact_team_game_stats.is_win (cleaner than fact_game.winner_team_id).

SEASON FILTERING:
  season_year column uses format '2023-24' (NOT 2023, NOT '2023')
  → Available on: fact_game, fact_team_game_stats
  → For fact_player_game_stats, JOIN fact_game ON game_id to filter by season
  → "last season" = '2023-24' | "this season" = '2024-25'
  → Always filter by season_year unless explicitly spanning multiple seasons

GAME STATS (per-game grain):
  fact_player_game_stats: game_id, person_id, team_id, opponent_team_id,
    is_home (BOOLEAN), is_win (BOOLEAN), starting_position (VARCHAR),
    comment (VARCHAR), num_minutes (DOUBLE),
    points, assists, blocks, steals, turnovers,
    fga, fgm, fg_pct, fg3a, fg3m, fg3_pct, fta, ftm, ft_pct,
    oreb, dreb, reb, fouls_personal, plus_minus,
    off_rating, def_rating, net_rating,
    ast_pct, ast_to_turnover_ratio, ast_ratio,
    oreb_pct, dreb_pct, reb_pct, tov_pct,
    efg_pct, ts_pct, usg_pct, pace, pie
  -> season_year is NOT a column on this table. To filter by season, JOIN
     fact_game g ON s.game_id = g.game_id and use g.season_year.
  -> When the user asks for career/aggregate stats without specifying a
     season, OMIT the season filter — do NOT default to '2023-24'.

PLAY-BY-PLAY:
  fact_play_by_play: player_name (VARCHAR, direct — no join needed),
    period (INTEGER: 1-4 reg, >4 OT), clock (VARCHAR MM:SS format),
    action_type (VARCHAR), shot_value (INTEGER: 2 or 3)
  → Clutch = period >= 4 AND clock <= '02:00'

BETTING ODDS:
  fact_game_main_line: game_id, moneyline_home, moneyline_away, spread, over_under

COMMON PATTERNS (copy these patterns exactly)

PPG leader this season:
  SELECT p.first_name || ' ' || p.last_name AS player_name,
         AVG(s.points) AS ppg,
         COUNT(s.game_id) AS games
  FROM fact_player_game_stats s
  JOIN dim_player p ON s.person_id = p.person_id
  JOIN fact_game g ON s.game_id = g.game_id
  WHERE g.season_year = '2023-24'
  GROUP BY p.person_id, p.first_name, p.last_name
  HAVING COUNT(s.game_id) >= 10
  ORDER BY ppg DESC
  LIMIT 10

Team season record:
  -- IMPORTANT: dim_team has multiple rows per team_id (historical franchise names).
  -- Aggregate fact_team_game_stats BEFORE joining dim_team to avoid row multiplication.
  -- PREFER using v_team_current for single-row-per-team name lookups.
  WITH team_stats AS (
    SELECT team_id,
           COUNT(*) AS games,
           SUM(CASE WHEN is_win THEN 1 ELSE 0 END) AS wins,
           SUM(CASE WHEN NOT is_win THEN 1 ELSE 0 END) AS losses
    FROM fact_team_game_stats
    WHERE season_year = '2023-24'
    GROUP BY team_id
  )
  SELECT t.team_name, ts.games, ts.wins, ts.losses
  FROM team_stats ts
  JOIN v_team_current t ON ts.team_id = t.team_id
  ORDER BY ts.wins DESC
  LIMIT 30

Individual player season stats:
  SELECT p.first_name || ' ' || p.last_name AS player_name,
         COUNT(s.game_id) AS games,
         AVG(s.points) AS ppg,
         AVG(s.assists) AS apg,
         AVG(s.rebounds) AS rpg,
         AVG(s.fg_pct) AS fg_pct,
         AVG(s.fg3_pct) AS fg3_pct,
         SUM(s.fg3m) AS fg3m_total
  FROM fact_player_game_stats s
  JOIN dim_player p ON s.person_id = p.person_id
  WHERE s.season_year = '2023-24'
    AND p.first_name = 'Stephen' AND p.last_name = 'Curry'
  GROUP BY p.person_id, p.first_name, p.last_name
  HAVING COUNT(s.game_id) >= 1
  LIMIT 1

Head-to-head comparison:
  SELECT p.first_name || ' ' || p.last_name AS player,
         AVG(s.points) AS ppg,
         AVG(s.assists) AS apg,
         AVG(s.rebounds) AS rpg
  FROM fact_player_game_stats s
  JOIN dim_player p ON s.person_id = p.person_id
  WHERE s.season_year = '2023-24'
    AND (p.last_name = 'James' OR p.last_name = 'Durant')
  GROUP BY p.person_id, p.first_name, p.last_name

Clutch plays:
  SELECT player_name, action_type, COUNT(*) AS count
  FROM fact_play_by_play
  WHERE period >= 4 AND clock <= '02:00'
    AND shot_value = 3
  GROUP BY player_name, action_type
  ORDER BY count DESC
  LIMIT 20

═══════════════════════════════════════════════════════
DUCKDB-SPECIFIC SYNTAX
═══════════════════════════════════════════════════════
- String concat: || operator (NOT CONCAT())
- Boolean: TRUE/FALSE (not 1/0 in WHERE)
- Integer division: use CAST(x AS DOUBLE) / y for decimals
- ILIKE for case-insensitive LIKE
- Date math: DATE_DIFF('day', start_date, end_date)
- ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)
- No PIVOT syntax — use conditional aggregation instead

═══════════════════════════════════════════════════════
ACCURACY GUARDS
═══════════════════════════════════════════════════════
- Always join dim_player via person_id (never filter by player name in fact tables directly, except fact_play_by_play which has player_name column)
- Always add HAVING COUNT(*) >= 5 for per-player rate stats (ppg, fg_pct, etc.) to filter noise
- For team stats, use fact_team_game_stats NOT fact_player_game_stats aggregated
- Check schema sample values to use exact string values in WHERE clauses
- When season is unclear, default to '2023-24'
- FORBIDDEN column aliases — never use these short names, always use the exact names listed in SCHEMA PATTERNS above:
  BAD → CORRECT: reb→rebounds (but the column IS named 'reb' — use 'reb') | num_minutes→minutes (correct) | pts→points (use 'points')
- CRITICAL: season_year filter is MANDATORY on fact_game, fact_player_game_stats, and fact_team_game_stats UNLESS:
    (a) The user asks about an all-time record ("most points in a game ever", "highest career avg")
    (b) The user explicitly says "career" or "all-time"
    (c) Multiple seasons are requested
  Omitting the filter on single-season queries silently aggregates all seasons and produces wrong game counts (an NBA team plays exactly 82 regular-season games per season; any single-team count above 90 for a single-season query is a bug). Always include WHERE s.season_year = '...' in single-season queries.
